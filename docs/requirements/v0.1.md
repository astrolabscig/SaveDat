# SaveDat v0.1 Requirements

Status: draft
Last updated: 2026-09-27

## Purpose

SaveDat answers one question about your files: if a storage device
disappeared right now, what would you actually lose?

It looks at the folders you point it at, works out which files exist in
only one place, and tells you what is exposed, how much of it there is,
and which device holds the only copy.

v0.1 analyses and reports. It does not copy, move or protect anything.

## Definitions

- **Location**: a folder on disk that SaveDat scans, given on the command line.
- **Device**: a physical storage unit, declared by the user as a label.
  Several locations may share one device label.
- **Content**: the bytes of a file, independent of its name or path.
- **Independent copy**: identical content found on a different device.
- **Single point of failure**: content whose only copies live on one device.

## Functional requirements

- FR-1: The tool accepts one or more locations on the command line, each
  tagged with the device it lives on, in the form `label=path`.
- FR-2: The tool rejects malformed input with a message naming the problem,
  and exits with a non-zero status.
- FR-3: The tool walks each location recursively and records every file's
  path, size in bytes, and last-modified time.
- FR-4: The tool identifies files by the content of their bytes, not by name,
  using a SHA-256 digest.
- FR-5: The tool groups files with identical content, across all locations.
- FR-6: For each group of identical content, the tool counts how many
  distinct devices hold it.
- FR-7: The tool reports content held on only one device as a single point
  of failure, regardless of how many copies exist on that device.
- FR-8: The tool reports duplicate copies of the same content on one device
  separately, as space used without protection gained.
- FR-9: The tool reports, per location, the number of files and total bytes.
- FR-10: The tool reports the total size of all content that has no
  independent copy.
- FR-11: The tool can simulate the loss of one named device and list the
  content that would have no remaining copy, with a count and total size.
- FR-12: Results are ordered by size, largest first.
- FR-13: Any path the tool cannot read is reported as unknown, with the
  reason, and included in the output.

## Non-functional requirements

- NFR-1: The tool never creates, modifies, moves or deletes any file in the
  locations it scans. It is strictly read-only.
- NFR-2: The tool never loads an entire file into memory. Files are read in
  fixed-size chunks.
- NFR-3: An unreadable file or folder never stops the run. It is recorded and
  the scan continues.
- NFR-4: The tool reports what it observed, at the time it observed it, and
  makes no claim about the present state of any device.
- NFR-5: The tool runs on Windows and Linux without code changes.
- NFR-6: Output is plain text, readable in a terminal without other tools.
- NFR-7: Every behaviour listed under functional requirements is covered by
  an automated test.

## Constraints

- C-1: Java only, targeting Java 21.
- C-2: The Java standard library plus a test framework. No other dependencies
  without a recorded reason.
- C-3: No budget. Everything used must be free.
- C-4: No saved state between runs and no database in this version.
- C-5: No network access of any kind.
- C-6: Written by someone learning Java, so clarity beats cleverness.

## Out of scope for v0.1

- Copying, backing up, syncing or restoring files
- Deleting duplicates or changing anything on disk
- Saved state between runs, caching, or incremental rescanning
- Cloud, NAS or network storage
- Recovering deleted files
- File version history, and detecting stale copies by name
- Protection policies and rules per folder
- Concurrency
- A graphical or web interface
- Automatic detection of physical devices

## Definition of done

v0.1 is finished when every functional requirement above is implemented and
covered by a passing test, the tool runs correctly against a real set of
folders across at least two real devices, the README explains installation,
usage and limitations, and the release is tagged v0.1.0.
